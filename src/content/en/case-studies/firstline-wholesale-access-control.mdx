## The real problem

Firstline's entire catalog, 17,500 SKUs with their prices and stock, was visible to anyone. It should have been visible only to an approved wholesale buyer, and the registration flow already in place was not hardened enough to hold that line: nonce and capability checks were missing, email verification was not enforced, and there was no formal buyer state machine.

This is a production store with active buyers and a live Cin7 sync, so I proposed a phased roadmap and had it approved before touching anything: stabilize caching and backups, audit authentication, define buyer access states, optimize filtering, lock the catalog server-side, and only then choose a wholesale pricing plugin. The order is deliberate. You do not settle pricing before you have settled who can see it.

Access is governed by user state rather than new WordPress roles, which would have created migration risk across an existing user base with mixed roles. It lives in its own plugin rather than the theme, so it can be rolled back safely. And because state, pricing, stock, and cart are all dynamic, I took the private catalog routes out of page cache entirely: performance there rests on taxonomy queries and object caching instead.
