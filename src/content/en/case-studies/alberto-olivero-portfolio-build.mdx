## The real problem

The site reuses the case-study architecture from my own portfolio, but the implementation drifted along the way: pages ended up rendering from a flat TypeScript data file instead of live MDX, so the whole MDX path was shipping with nothing using it. And that path carried `next-mdx-remote` pinned to a version flagged under CVE-2026-0969.

I found it sideways. Migrating from npm to pnpm immediately surfaced a TypeScript error, `Cannot find module 'mdx/types'`, that npm's flat hoisting had been quietly hiding. Chasing it confirmed the path was dead, so I removed all of it: the loader, the components, an orphaned example file, and five dependencies that existed only to hold it up. 146 fewer packages in the tree.

I then audited the production code. These findings are documented and prioritized, but not yet implemented: project images shipping as 700KB to 2.2MB PNGs with no `sizes` prop and no `priority` on the largest above-the-fold image, inline SVG markup duplicated across pages instead of a shared component, `usePathname()` called once per navigation link, and `metadataBase` missing from the root layout.
